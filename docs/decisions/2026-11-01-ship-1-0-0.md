# Ship Khalid 1.0.0, outside checks after launch, 2026-11-01

The final 1.0 readiness pass (`khalid-ops/ready-1.0-final.md`, on main `618058f4`) said "not ready" and named four blockers. Two of them were checks this repository's machines cannot run. The founder decided on 2026-11-01.

## The decision

- **Khalid ships as 1.0.0.** The founder approved it on 2026-11-01. 1.0.0 is the first stable release: it holds everything in 0.9.1 and the fixes from the readiness passes.
- **These checks run after launch, not before it:**
  - Ahrefs or Semrush Site Audit on the demo site (KH-LNT-5).
  - `khalid serve --domain` against a live Let's Encrypt certificate (KH-INS-4).
  - The Astro and Next.js starter kits deployed against a live blog (KH-INS-5).
  - SerpDad's own blog running on Khalid (PRD metric).
- **Why:** each one needs a public server, an outside account or a person. None can lose a user's posts, and each has a fallback today: Khalid's own audit gives a new site 100, HTTPS passes against a test certificate authority on every change and can be handed to a web server in front, and the starter kits are examples.
- **Where users read it:** `docs/releases/1.0.0.md` lists them under "Still checked after launch". What they find goes in the next release's notes.

## What the version covers

As for 0.9.x (`2026-10-31-first-release-0-9-0.md`): every crate that inherits `[workspace.package]` carries 1.0.0, and so do the TypeScript SDK, the admin's `package.json` and the API's OpenAPI document. `khalid-core` and `khalid-lint` keep their own published version, 0.1.0, which moves with their own API. The 0.9.0 decision said they reach 1.0.0 with the product, but neither is on crates.io yet, and a 1.0.0 there is a promise to their outside users. They move to 1.0.0 in their own pull request once they are published and their API has settled. Third-party crates are never touched by a version bump.

## Who does what

Unchanged from 0.9.0: agents prepare the release pull request and never tag. The founder, or the CTO session on the founder's word, pushes `v1.0.0` on `main` once the pull request lands, then reads the draft release and presses Publish.
