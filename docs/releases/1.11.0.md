# Khalid 1.11.0

Khalid 1.11.0 knows the whole schema.org vocabulary. It checks the schema you write by hand, shows what is wrong in two plain reports with buttons that fix it, suggests and fills in schema from what a post says, and checks the schema of any page or pasted code in the admin.

Schema is the hidden description of a page that search engines read, such as "this is a recipe, it takes 20 minutes". Good schema helps a page show as a rich result, with stars, prices or steps.

## Added

- **The whole schema.org vocabulary.** Khalid now knows every type, property and allowed value in schema.org release 30.1. A typing slip in any name you write by hand, such as `TouristAtraction` for `TouristAttraction`, is caught, not only slips in common names.
- **Deeper checks on schema you write by hand.** `khalid lint` and the editor now warn when:
  - a property does not belong to its type
  - a value is not what the property expects, such as a real date, a number, a web address, a currency code or an allowed value like `InStock`
  - a nested item has a type that does not fit
  - an `@id` points to nothing on the page
  - schema.org has replaced a name
  - a price, name or other detail in the markup never appears in the post

  These are warnings, so the post still publishes.
- **Two reports with one-click fixes.** The editor's Schema panel shows two reports: "Is it correct schema.org?" and "Can Google show it as a rich result?". Each finding says where it is, what is wrong and what to do. A finding with one clear fix has a button that makes it, such as "Change pricecurrency to priceCurrency".
- **Schema suggested from what a post says.** The Schema panel suggests schema beyond what the post type gives:
  - a recipe for ingredients and a method
  - an article for a byline and a date
  - a product for prices
  - a local business for an address
  - questions and answers for headings that ask questions

  Each suggestion names the type, the reason and how sure Khalid is.
- **Schema filled in from the post.** Each suggestion has a button that fills the schema from the post. It can fill prices with their currency, the address, phone number and opening hours, the author and date, ingredients and steps, questions and answers, a breadcrumb trail and social profile links. Check each value, then save.
- **A schema check for any page.** The new Schema check screen, under Grow in the admin menu, checks the schema of any page address or of code you paste, in the same two reports. Use it to check your old site's pages before you move them to Khalid.
- **The same checks for programs.** Programs can run these checks through the Admin API at `POST /api/admin/v1/schema/checks/`, with pasted code or `{"url": "https://..."}`.

## Changed

- **Libraries brought up to date.** comrak, the library that turns posts into pages, moves from 0.59 to 1.1, and ten other libraries take their latest small releases. Pages come out the same as before.

## Upgrading from 1.10.0

Install 1.11.0 over it the same way you installed 1.10.0, and restart `khalid serve`. Your site folder needs no change. Take a `khalid backup` first if you want a copy to go back to.

- **Script:** `curl -fsSL https://raw.githubusercontent.com/thebigasif/khalid/main/scripts/install.sh | sh -s -- --version v1.11.0`
- **Docker:** use `ghcr.io/thebigasif/khalid:1.11.0`.
- **From source:** `git clone --branch v1.11.0 https://github.com/thebigasif/khalid.git`, then the steps in `CONTRIBUTING.md`.

`khalid --version` then prints `khalid 1.11.0`. Things to know:

- **Run `khalid lint` once.** The deeper schema checks may name problems in schema you wrote before. They are warnings, so nothing stops publishing.

## Still checked after launch

Three of the four checks promised after 1.0.0 are still open. [The after-launch page](after-launch.md) says where each stands, what our tests prove meanwhile and what to do if it matters to you.

- **Ahrefs and Semrush on the demo site.** Still open. On every change, Khalid's own audit must give the demo site and the showcase site 100.
- **HTTPS with a live Let's Encrypt certificate.** Still open. On every change to the HTTPS code, our tests get and renew a certificate from Let's Encrypt's test server.
- **The Astro and Next.js starter kits, deployed.** Still open. Our tests build both kits against the showcase blog whenever the kits, the API or the page renderer change.

## Checking a download

Each release has a `SHA256SUMS` file. The install script checks against it for you. By hand, run `sha256sum -c SHA256SUMS --ignore-missing` in the folder that holds the download.
