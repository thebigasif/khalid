# Khalid 1.10.0

Khalid 1.10.0 lets you close or turn off comments and tells you about each new one, sends your newsletter digest by itself, imports readers and comments from other platforms, shows the alerts that need you on the dashboard, gives pages the same search and sharing settings as posts, and links every lint message to a guide.

## Added

- **Comments open, closed or off.** Set comments for the whole blog in the admin's Settings screen, or in `site.toml` under `[comments]`, and for one post in the editor's More settings. A closed post keeps its comments and says it is closed. A post with comments off shows none.
- **An email for each new comment.** When your site sends mail, owners and admins get an email for each new reader comment, with its text and a link to the Comments screen, so none waits unseen. The reader's email address is never in it. `notify = false` under `[comments]` stops these emails.
- **The newsletter digest sends itself.** Put a `digest.toml` with `every = "week"` or `"day"` in a newsletter's folder, and `khalid serve` emails the posts published since the last digest when one is due. With nothing new it sends nothing.
- **Readers in and out.** The Subscribers screen has Import and Export buttons. An import reads Khalid's own export, a Substack email list or a Ghost members export, and says how many readers it adds before it saves anything. Readers keep the status they had, with no confirmation email.
- **Know who gets a send.** Before you send a post to readers with certain labels, the Subscribers screen says how many readers that is, and the button says "Send to 38 readers".
- **More from an import.** A WordPress import brings the comments under each post. WordPress, Ghost and markdown imports now write tags, the search title, co-authors, the feature image and share cards into each post, where before the report only listed them.
- **Alerts on the dashboard.** "Alerts for you" on the dashboard shows what needs you, such as a site that is down, a certificate near its end, stale posts or a crawler that stopped coming. Each alert says what happened, why it matters and what to do. Programs read the same list through the Admin API and the MCP tool `list_alerts`.
- **Pages get search and sharing settings.** A page, such as About, can be hidden from search engines, name its original address, show a feature image, and set what Facebook and X show when someone shares it. Its screen in the admin has these under "Search and sharing".
- **A page's address can change.** Change a page's address in the admin, and the old address sends readers and search engines to the new one, so no link breaks. Deleting a page asks whether its old address should say the page is gone or send readers somewhere else.
- **Every lint message links its guide.** `khalid lint`, the dashboard and the editor's checks panel now link each problem to its section on the new "What the linter checks" page.
- **Links inside your site are checked.** `khalid lint` now checks ordinary links to your own site's addresses too. A link to an address with no page gets a `broken-internal-link` warning, and a link to an address you moved gets `redirecting-link` with the new address to use.
- **More fields in the editor.** The editor's settings panel has fields for tags, category, the featured switch, who may read the post, a reader password, a custom template and code for the page head.
- **Your words on more pages.** `theme/strings/<language>.toml` can also word the page a refused comment shows, the newsletter's emails and sign-up pages, and the notes a static site shows where a form was.
- **Every post field through the Admin API.** Programs can now set a post's translation, related posts, series, topic cluster, sitemap and listing settings, everything its front matter holds.
- **Long lists a page at a time.** Admin API lists, such as tags, pages, redirects, keys and the trash, take `page`, `limit` and `filter`, so a big site no longer comes back in one answer. A request without them still gets the whole list.

## Changed

- **Smaller share pictures.** The picture a post shows when it is shared is saved in a smaller form: the same pixels in about 37% fewer bytes, drawn in about half the time.
- **A smaller program.** The Linux program is about 1.5 MB smaller, which makes room for everything new in this release.
- **Libraries brought up to date.** The template engine, the font reader, the folder watcher, the certificate names and the Brotli compressor take their latest releases.

## Fixed

- **Your own words everywhere.** Words you set in `theme/strings/<language>.toml` now also reach month names, reading times, "Written by" in link previews, the imprint link and opening hours.
- **Setting the author on many posts.** The posts table's "Set the author" now offers every author of the blog, not only the authors of the posts on the page.

## Security

- **Mail and cleaned HTML.** Mail goes out through lettre 0.11.24, which fixes six flaws a hostile mail server could use. HTML that arrives in a post, through the API or by import, is cleaned by ammonia 4.2.5, which closes a cross-site scripting hole through embedded SVG and MathML.
- **Links that crash.** url 2.5.9 fixes a crash: a link wrapped in thousands of `blob:` prefixes could stop Khalid (RUSTSEC-2026-0592).

## Upgrading from 1.9.0

Install 1.10.0 over it the same way you installed 1.9.0, and restart `khalid serve`. Your site folder needs no change. Take a `khalid backup` first if you want a copy to go back to.

- **Script:** `curl -fsSL https://raw.githubusercontent.com/thebigasif/khalid/main/scripts/install.sh | sh -s -- --version v1.10.0`
- **Docker:** use `ghcr.io/thebigasif/khalid:1.10.0`.
- **Homebrew:** `brew upgrade khalid`.
- **From source:** `git clone --branch v1.10.0 https://github.com/thebigasif/khalid.git`, then the steps in `CONTRIBUTING.md`.

`khalid --version` then prints `khalid 1.10.0`. Things to know:

- **Comment emails start at once.** If your site sends mail, owners and admins now get an email for each new comment. To stop them, add `notify = false` under `[comments]` in `site.toml`.
- **One way to send the digest.** If a timer runs `khalid newsletter digest` for a newsletter today, either keep it or add `digest.toml` and remove the timer. Do not use both, or readers may get two digests.
- **Run `khalid lint` once.** The new `broken-internal-link` and `redirecting-link` warnings may name links that were already there. They are warnings, so nothing stops publishing.
- **Building on Linux.** Building Khalid from source on Linux now needs glibc 2.36 or newer. The release downloads run everywhere they did.
- **Old share pictures stay.** Share pictures drawn before stay as they are until the post changes. Delete `data/share/` to draw them all again in the smaller form.

## Still checked after launch

Three of the four checks promised after 1.0.0 are still open. [The after-launch page](after-launch.md) says where each stands, what our tests prove meanwhile and what to do if it matters to you.

- **Ahrefs and Semrush on the demo site.** Still open. On every change, Khalid's own audit must give the demo site and the showcase site 100.
- **HTTPS with a live Let's Encrypt certificate.** Still open. On every change to the HTTPS code, our tests get and renew a certificate from Let's Encrypt's test server.
- **The Astro and Next.js starter kits, deployed.** Still open. Our tests build both kits against the showcase blog whenever the kits, the API or the page renderer change.

## Checking a download

Each release has a `SHA256SUMS` file. The install script checks against it for you. By hand, run `sha256sum -c SHA256SUMS --ignore-missing` in the folder that holds the download.
