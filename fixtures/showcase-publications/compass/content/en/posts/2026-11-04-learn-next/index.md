What to learn next after your first website depends on what you enjoyed most while building it: more JavaScript if you liked making things react, design and accessibility if you liked how it looked, a back-end language if you wondered where data is stored, or simply a second, bigger website. Pick one route, follow it for three months, and leave the others for later.

Finishing a website is a real milestone. Most people who start learning to code never get there. This guide helps you decide where to point your next three months, so the momentum does not fade.

::toc

:::callout{kind=summary}
- **Follow your enjoyment.** The part you liked most is the best clue to your next route.
- **One route at a time,** for about three months.
- **Keep building things.** Every route works best around a real project.
- **Review your first site** after a month: you will see how much you have learned.
:::

## First, improve the site you have

Before you choose what to learn next, spend two weeks on version 2 of your website. Go back to the list of three changes you wrote at the end of [step 4](/blog/publish-website/). Making them teaches you something every working developer does daily: changing code that already exists without breaking it. Commit each change separately with Git, so you practise that habit too.

## Four routes to learn next

| Route | You will learn | Pick it if you enjoyed | What it can lead to |
|---|---|---|---|
| More JavaScript | Arrays, functions, fetching data, building small tools | The button that showed and hid your list | Front-end development |
| Design and accessibility | Layout with Grid, typography, colour contrast, screen readers ([an introduction from the W3C](https://www.w3.org/WAI/fundamentals/accessibility-intro/)) | Choosing fonts and spacing | Web design, accessibility work |
| A back-end language | A language that runs on the server, databases, forms that save data | Wondering how sign-in or comments work | Back-end or full-stack development |
| A bigger website | Templates, many pages, a site generator | Writing the content itself | Running sites for clubs, charities or a small business |

None of these is the "right" next step. Developers on all four routes earn a living, and many switch routes after a few years.

## Choose what to learn next, step by step

::::howto{name="Choose what to learn next" time="0:45:00"}
:::step{name="Look back at your learning log"}
Read your log from the past few months. Mark the sessions you remember enjoying, and the ones that dragged.
:::
:::step{name="Match them to a route"}
Find the route in the table whose "Pick it if you enjoyed" column best matches the sessions you marked.
:::
:::step{name="Choose a project for that route"}
Pick one small thing to build that needs the new skill: a quiz for JavaScript, a redesign of your site for design, a form that saves messages for back end.
:::
:::step{name="Book three months"}
Keep the same practice rhythm you used on this path, about three hours a week, and put a review date in your diary twelve weeks away.
:::
::::

## A first taste of each route

If you are still unsure what to learn next, try a small exercise from each and notice which one you want to carry on with.

For JavaScript, open the console and run this. It counts the words in a sentence:

```javascript
const sentence = "I built a website and put it online";
const words = sentence.split(" ");
console.log("That sentence has " + words.length + " words.");
```

For design, add this to your site's stylesheet and see how the home page changes:

```css
main {
  display: grid;
  gap: 24px;
}
```

For a back-end language, read your notes on [how the web works](/blog/how-web-works/) again, and ask yourself what the server would need to do to remember a visitor's name. If that question excites you, the back end is your route.

:::callout{kind=tip}
Whatever you choose, keep reading other people's code. Inspect sites you like with the [developer tools](/blog/browser-developer-tools/), and notice one thing on each that you did not know before.
:::

## Signs you are ready for a job

Some students start the path to change career. If that is you, three signs say you are getting close: you have built three or more projects without following a guide step by step, you can read an unfamiliar error and find the fix on your own, and you can explain your code to someone else. That usually takes a year or two of steady practice after your first website. It took Ruben, who writes our project series, a little under two.

:::callout{kind=note}
You do not need to want a job in tech for any of this to be worth it. Many of our students code for their club, their own business or simply because they like making things.
:::

Whatever you learn next, the habit you built on this path is what carries you. Keep it going, and come back to the [start of the path](/blog/start-coding/) whenever you want to see how far you have come.
